# Onboarding ten-step functional audit

Date: 2026-10-11. Scope: current local checkout, including pre-existing uncommitted edits. This is a source audit plus focused local tests, not a production certification. The machine-readable field/action matrix is `ONBOARDING_AUDIT_MATRIX.json`.

## Architecture and actual route map

`/onboarding` mounts `ExactScreensContainer` at screen 2. `/screens` is a gallery/deep-link route; gallery sample records are isolated behind `isGalleryMode`. The container owns transient state. `GET/PUT /api/onboarding-v2` restores/saves a `safeDraft` in `onboardingDrafts` keyed by `personId`. `GET /api/auth/session` supplies an authenticated identity. Guests are created by `getOrCreateOnboardingAuthContext` and receive an HTTP-only session cookie. CV upload uses `/api/resume/extract`, `document-parser-service`, deterministic extraction, `sourceSnapshots`, and `resumeReviewed`. Digital import uses `/api/student/footprints/sync` and `DigitalSourceImportOrchestrator`. Completion calls `/api/onboarding-v2` POST, writes profile/evidence/projects/preferences, then redirects to `/student`; `/api/student/person-360` reads the saved person data.

The ten-step registry (`lib/onboarding-step-registry.ts`) originally called Step 4 academic and Step 5 resume, while the CV-first container renders Step 4 resume and conditional Step 5 academic. The registry now uses the actual screen indices and order. The rendered skills map remains an extra unnumbered screen after Step 8; welcome is a prelude, not one of the ten. The boundary test asserts the full mapping.

## Tests and limitations

`npm run typecheck`, `npm run lint -- --quiet`, `node --import tsx scripts/verify-onboarding-boundaries.ts`, synthetic parser/OCR test, local browser checks, local sequential manual and CV paths, and local in-memory HTTP test passed during this audit. Remaining limits include mobile layout, refresh/re-login, live external import, a full CV-to-dashboard path, Neon and Vercel preview. The live onboarding initial page opened read-only with a blank name field and no console errors. No production data was migrated, reset or directly queried.
